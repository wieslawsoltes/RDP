LOCAL TCP / TLS / WEBSOCKET

Connect your browser.

The browser client runs on GitHub Pages. The gateway runs on your computer, where it can reach your RDP server.

1. Start the gateway

Install Node.js 22 or newer and obtain the source repository. No npm dependencies are needed.

git clone https://github.com/wieslawsoltes/RDP.git
cd RDP
npm run gateway:init

Edit .rdp-gateway/targets.json. Set the destination host, port and TLS server name. Use a trusted CA with caFile, or an independently verified certificate fingerprint with certSha256. Do not paste passwords into this file.

npm run gateway -- --allow-origin https://wieslawsoltes.github.io

Paste the printed gateway address and private token into the connection form, press Load targets, select your target and enter credentials. Tokens and passwords remain in memory and are not added to URLs or saved profiles. Restarting the gateway rotates its default token.

2. When the browser requires WSS

Public HTTPS pages may be prevented from opening a local HTTP/WebSocket connection. Browser and operating-system Local Network Access permissions can also apply. Do not disable browser security or use an insecure certificate bypass.

Use an HTTPS certificate trusted by your browser and covering the exact local gateway hostname. For development, a locally trusted certificate authority can issue a certificate for localhost, 127.0.0.1 and ::1. Keep its private key out of the repository.

npm run gateway -- --allow-origin https://wieslawsoltes.github.io \
  --https-cert /path/to/localhost.pem --https-key /path/to/localhost-key.pem \
  --public-origin https://localhost:8787

Enter https://localhost:8787 as the gateway. The client derives wss://localhost:8787/bridge. The gateway certificate and the remote RDP server certificate are separate trust checks.

Same-origin fallback: open the local workspace address printed by the gateway. It serves the same application and avoids public-site-to-loopback restrictions. The offline protocol lab requires no gateway connection.

Security boundary

The local gateway terminates TLS/CredSSP and sees credentials and decrypted RDP traffic. Keep it on loopback; do not expose its port publicly. It accepts only exact allowed browser origins, an access token, and target IDs from your local allowlist. It is not an unrestricted TCP proxy or Microsoft's RD Gateway protocol.

All projects under the same GitHub Pages hostname share a browser origin. Paths such as /RDP do not isolate trusted web applications. A dedicated custom hostname or the local same-origin workspace provides a narrower trust boundary.

The static deployment contains only client-side files. The gateway and your target configuration never execute on GitHub Pages. A green deployment does not establish complete RDP conformance or independent Windows interoperability.

Troubleshooting

401: token incorrect or gateway restarted. 403: exact browser origin or gateway Host rejected. WebSocket failure: check gateway address, browser local-network permission, and trusted HTTPS certificate. Target denied: edit the local allowlist. Certificate error: verify the remote server CA/fingerprint; do not bypass verification. Licensing error: the current RDP client still lacks full CAL issuance/renewal support.
